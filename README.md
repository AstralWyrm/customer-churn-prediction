# Customer Churn Prediction from Scratch

Entropy-based decision trees and ensembles implemented in Python, with a fully
executed experiment notebook, reproducible metrics and automated tests.

## What it does

Predicts whether a telecom customer will churn within 30 days. The learner uses
categorical multiway splits and numerical binary splits, then combines trees
through bagging, random forests and validation-weighted voting. No machine
learning library implements the models.

- Information gain and majority-class leaves; deterministic ties favour class 0.
- Every midpoint between consecutive distinct numerical values is considered.
- Cumulative label counts make numerical split search O(n log n) per feature.
- Bootstrap sampling with replacement; random feature subsets at **each node**.
- Validation-weighted shallow trees, with an equal-vote control on identical trees.
- Early stopping based on node sample count and minimum information gain.
- Master seed **3411**, with deterministic child seeds and reset bootstrap RNGs.

## Quick start

Use Python 3.10 or newer. Core code and tests require no third-party packages.
From the project directory:

```bash
python trees.py
python experiments.py
python -m unittest discover -s tests -v
```

`trees.py` prints dataset information and the majority-class baseline.
`experiments.py` runs **all** experiments and writes `results/results.json` and
`results/metrics.csv`. The supplied `report.ipynb` already contains full outputs
and explanations. CLI data paths are resolved relative to the script, so they do
not depend on the terminal's working directory.

Optional notebook environment:

```bash
python -m pip install -r requirements-notebook.txt
python -m jupyterlab report.ipynb
```

Run notebook cells in order from the project directory. Timings vary by machine.

## Data and evaluation

The supplied course dataset contains 840 training, 180 validation and 180 test
rows. The 15 inputs comprise 8 categorical and 7 numerical features. `customer_id`
(a synthetic identifier) and `churned` are excluded from inputs. Feature meanings
are in [data/data_dictionary.md](data/data_dictionary.md).

The training majority label is 0. That **same label** supplies the baseline on all
three splits. Baseline accuracies are 0.6190 / 0.6167 / 0.6444 for train /
validation / test, with churn-class F1 of 0 throughout. Every evaluation prints
accuracy, positive-class F1 and the corresponding baseline. Test labels are used
for final reporting, never to fit trees or determine voting weights.

The data files are included here for a runnable portfolio project. They were
supplied with the original course exercise; see [NOTICE.md](NOTICE.md).

## Recorded results

The baseline row applies to every model below. “Depth” means actual depth for a
single tree and mean depth for an ensemble. All values are generated by the
included code; the complete train/validation/test results are in
[results/metrics.csv](results/metrics.csv).

| Model | Validation accuracy | Validation F1 | Test accuracy | Test F1 | Depth |
|---|---:|---:|---:|---:|---:|
| Majority-class baseline | 0.6167 | 0.0000 | 0.6444 | 0.0000 | — |
| Bagging, B=20 | 0.6833 | 0.5128 | 0.7167 | 0.5984 | 12.90 |
| Random forest, B=10, m=3 | 0.6333 | 0.4211 | 0.7000 | 0.5000 | 14.50 |
| Equal-vote shallow ensemble, B=20 | 0.6944 | 0.4762 | 0.7278 | 0.5149 | 4.00 |
| Validation-weighted shallow ensemble, B=20 | 0.7000 | 0.5000 | 0.7333 | 0.5294 | 4.00 |
| Single mixed-feature tree, depth=3 | 0.6500 | 0.4522 | 0.7333 | 0.5789 | 3.00 |

The weighted shallow ensemble gives slightly better validation accuracy and F1
than equal votes on the same trees. It does not dominate every model on every
metric. A single depth-3 mixed-feature tree provides a compact explanation using
10 internal nodes; its validation performance trades off against the ensembles.
The validation-weighted model's validation score is a **tuning score**, because
those labels set the weights, rather than a fresh independent assessment.

## Experiment coverage

| Section | Experiment |
|---|---|
| 2.1 | Class counts, fixed seed, train-majority baseline |
| 2.2 | Categorical-only trees with depth 2, 3, 4, 5 and unrestricted |
| 2.3 | All four requested root thresholds, mixed-feature tree inspection |
| 2.4.1 | Bagging with 5, 10 and 20 trees |
| 2.4.2 | Random forests with m=3 and m=15; exact all-feature bagging check |
| 2.4.3 | Validation-weighted shallow ensemble; uniform-vote and single-tree controls |
| 2.4.4 | Bagging and forest, each with/without the same early-stopping rule |

The stopping rule requires at least 20 samples at a node and information gain of
at least 0.01 bits to split. Controls retain the original minimum of two samples
and strictly positive gain. Both conditions are applied inside the tree learner
and propagated through both ensemble variants. The paired runs use the same
bootstrap samples. Results show lower mean depth and shorter observed fit times,
but several F1 scores decline. The notebook discusses these measured trade-offs.
One fit timing per setting is descriptive, not a robust hardware benchmark.

## Design limits

This is an educational binary-classification implementation. Categorical values
not observed during training fall back to the current node's majority class.
Missing-value imputation is not implemented because the supplied data has no
missing fields. Numerical inputs must be finite, and feature schemas must match.
Prediction quality on one small fixed split does not establish production
performance. Weighted votes can favour the majority class and can overfit the
validation set. These limitations are recorded rather than hidden.
